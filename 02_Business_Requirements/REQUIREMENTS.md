# Business Requirements Baseline

## Business Goal

Create a transparent analytical product that helps stakeholders understand FDA MAUDE reporting patterns and data quality without overstating what passive reporting data can prove.

## Core Requirements

- BR-001: Source files must be assessed before transformation.
- BR-002: Malformed records must be identified and quarantined.
- BR-003: Distinct MAUDE report counts must be protected from device-level duplication.
- BR-004: Device-record counts must remain analytically distinct from report counts.
- BR-005: Monthly reporting trends must be reproducible.
- BR-006: Product/device analysis must support filtering and drill-down.
- BR-007: Event-type analysis must support reporting-pattern review.
- BR-008: Data-quality indicators must be visible to stakeholders.
- BR-009: Core dashboard metrics must reconcile to independent reference calculations.
- BR-010: Methodology and limitations must be visible.
- BR-011: Synthetic investigation/CAPA data must be clearly separated from FDA data.
- BR-012: Requirements must be traceable to tests and evidence.

## Interpretation Guardrail

The solution must not describe MAUDE report counts as failure rates, incidence, prevalence, or proof of causality.
